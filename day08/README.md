任意オプション

- `--max-steps`：最大ステップ数（整数、デフォルト `10`、1〜50）
- `--max-retry`：最大リトライ回数（整数、デフォルト `1`、0〜5）

- 正常終了：`0`
- 入力不備：`2`
- 実行失敗（上限到達含む）：`1`

## リサーチメモ（任意）

調べたURLや、理解した要点をメモしてください。

- リトライ設計（何を再試行するか）：LLMの出力フォーマット崩れ（JSONパース失敗など）は再試行で解消する可能性が高いため、リトライ（再生成ループ）の対象とする。
- フォールバック設計（縮退動作、聞き返し）：RAG検索における該当0件（ヒットなし）は同一条件で再試行しても結果が変わらず、そのまま生成に進むとハルシネーションの原因となるため、生成を行わずユーザーへ検索条件の変更を促す聞き返し（フォールバック）へ逃がす。
- 上限（最大回数、最大ステップ）：グラフ内にループ構造（`retry` → `execute`）を作る場合、AIの連続失敗による無限ループやAPIコスト暴走を防ぐため、State内でリトライ回数と総ステップ数をカウントし、上限超過時に強制終了させるストッパーが必須となる。

## 付録：復帰パスの設計メモ

### 復帰パス（リトライ/フォールバック）

- 失敗パターン：
  1. JSONパース失敗（`status == "json_error"`）
  2. RAG検索ヒットなし（`status == "no_hit"`）
- 復帰方法：
  1. JSONパース失敗：`retry_count < max_retry` の場合は `retry` ノードでカウントを増やし、`execute` ノードへ差し戻して再生成を行う。
  2. RAG検索ヒットなし：`fallback` ノードへ分岐させ、条件変更を促す聞き返し文面を出力して安全にフローを終了する。
- 上限（最大回数/最大ステップ）：
  - リトライ上限（`max_retry`）：条件分岐（`route_after_execute`）にて `retry_count` と比較し、到達時は `abort` ノードへ遷移させて例外（終了コード `1`）で停止。
  - ステップ上限（`max_steps`）：各ノード実行時に累計 `step_count` を加算して `_check_step_limit()` で検証し、超過時は即座に例外（終了コード `1`）を送出して停止。
