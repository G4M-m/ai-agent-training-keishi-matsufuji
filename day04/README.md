# Day 04

## 受講者が実装する場所

- `day04/app.py` の `run_chain()`

## 目的

- LangChainで処理を部品化してつなげる
- Tool callingの最小構成を作り、ツールの引数検証/制限を理解する

## ゴール（完了条件）

- LLMからツールが1回以上呼び出される
- 不正引数でツールが実行されない

## ツール仕様

- ツール名：
- 入力：
- 出力：
- 許可リスト/制限：

例（どれか1つでOK）

- 日付取得ツール（`today`）
- 簡易計算ツール（`add`/`multiply`）
- 固定データ検索（`lookup_company_policy` など、ローカル辞書から検索）

本研修テンプレでは、未経験者が迷わないよう、以下のいずれか1つを必須ツールとして実装してください。

- ツール名：`today`
  - 入力：なし
  - 出力：`YYYY-MM-DD`（文字列）

または

- ツール名：`add`
  - 入力：`a`（整数）, `b`（整数）
  - 出力：`a + b`（整数）

## 機能要件

コマンド

- `python -m day04.app` で起動できること（モジュール名は固定）

必須オプション

- `--text`：ユーザー入力（文字列、必須）

出力

- 標準出力に最終回答（文章）を出力する

終了コード

- 正常終了：`0`
- 入力不備：`2`
- 実行失敗（LLM/ツール呼び出し失敗等）：`1`

必須要件

- 上記の必須ツール（`today` または `add`）を実装し、LLMから1回以上呼び出す
- ツール引数を検証する（`add`の場合は整数のみ許可、など）
- ツール呼び出しに失敗した場合に、安全に失敗する（終了コード `1` でよい）

受け入れ基準

- ツールが呼び出されたことがログで分かる
- 不正な引数でツールが実行されない

## 実装タスク

- `day04/app.py` の `run_chain()` を実装し、機能要件を満たす
- ツール（`today` または `add`）を実装し、ログで呼び出しが分かるようにする

## 実行方法

### 実行コマンド例

```bash
# todayツールを使う例
python -m day04.app --text "今日の日付を教えて"

# addツールを使う例
python -m day04.app --text "123と456を足した結果を教えて"
```

```

今日は2024-12-01です。
```

## リサーチメモ（任意）
今回の実装を通じて、AIを業務システムへ統合するための核心的なアーキテクチャを学んだ。

- **コンテキスト保持の仕組みへの感動：**
AI自身はステートレスであるにも関わらず、Python側で `messages`（台本）のリストを管理し、処理のたびに履歴を `append` して渡し直すことでコンテキストを維持できる構造に深く感動した。これにより、システム側で前提条件や要件を固めた上でAIを組み込むことが可能になる。

- **確率的AIと決定論的システムの融合：**
計算や確定的な処理はPython側（決定論的）で担保し、自然言語の解釈や判断という確率的な領域だけをAIに任せるという役割分担が、LangChainを通じて見事に成立することを実感した。

- **自律的挙動の「すり抜け」リスクと制御の必要性：**
意図的に不正な引数（小数）を渡した際、Pythonのエラーで落ちるのではなく、AIが事前に要件を解釈し「自律的に代替計算案を提示する」という事象が発生した。デモとしては優秀だが、企業システムとしては「意図しない制御外の動き（すり抜け）」であり重大なリスクとなる。
このトライアンドエラーから、`SystemMessage` を用いてAIを厳密に制御する実装の必要性を痛感した。AIの柔軟性は時に脆弱性となるため、「想定外の使われ方をいかに塞ぐか」というテスト観点と実装観点が今後のシステム設計において極めて重要になる。
